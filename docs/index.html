The Story: Why We Built This

When auditing, debugging, or learning from open-source libraries, looking into node_modules is painful. The code is bundled, minified, stripped of original comments, missing unit tests, and devoid of commit history.

What developers actually want is the authentic upstream source code.

Instead of manually hunting down 20 different repository URLs across GitHub, opening 20 browser tabs, and running 20 manual git clones, you run one command in an empty workspace: 

mkdir audit-express && cd audit-express
npx @keshavsoft/npm-source-explorer express

How It Works: The 4-Act Engine

The core architecture is built upon a clean 4-act story pipeline that separates dependency discovery from Git cloning:

Act 1: The Gatekeeper

Validates target package specifications, parses scoped packages (@scope/pkg), and determines root package identity and owner.

Act 2: The Cartographer

Spins up an isolated sandbox in os.tmpdir() and builds the full transitive dependency tree using @npmcli/arborist.

Act 3: The Detective

Traces authentic Git remotes, applies smart owner fallback for missing repos, deduplicates, and produces the Source of Truth manifest.

Act 4: The Builder

Executes fail-safe shallow cloning (--depth 1) side-by-side with 25s timeouts and process-tree termination (Windows taskkill).

Architecture & Decoupling

Acts 1–3 output a pure JSON Source of Truth manifest containing canonical Git remotes. Act 4 consumes that manifest to build the workspace.

This clean boundary allows the codebase to be used either as an all-in-one developer tool or split into two specialized packages:

  • @keshavsoft/npm-repo-resolver: Discovers dependency trees and outputs the Source of Truth manifest.
  • @keshavsoft/git-sibling-cloner: Takes any repository manifest and shallow-clones sibling workspaces with process fail-safes.
